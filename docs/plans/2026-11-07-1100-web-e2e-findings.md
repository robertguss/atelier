## High

### F1. The runner on the VM is older than the raise_hand work

- Seen: in a room with Codex and Pi, the agent pane shows "Codex can't raise
  question cards" and "Pi can't raise question cards". Codex listed its room
  tools as `add_block, comment, delete_block, read_document, read_thread,
  update_block`, and Pi listed the same six. Neither has `raise_hand`,
  `read_handbook` or `recent_decisions`.
- Cause: `canRaiseCards: true` for Codex and Pi, and the three tools, landed in
  9e6cd7c (13:46 UTC). The runner reports capabilities only at registration
  (`runner/src/index.ts:107`, `runner.reportCapabilities`), so the running
  process predates that commit. The VM checkout is on
  `feat/atelier-mcp-tools` at 29c2305, which has the code.
- Fix: restart the runner from current `main` and confirm the badges disappear
  and Codex can raise a card.

### F2. Invites fail: `CLERK_SECRET_KEY is not set`

- Repro: Members, invite any valid address. The sheet shows the raw error
  "CLERK_SECRET_KEY is not set" (`packages/backend/convex/invites.ts:74`).
- Cause: operator setup step missing on the Convex deployment the web app uses
  (see docs/shared-rooms.md, Operator setup, Convex).
- Fix: `npx convex env set CLERK_SECRET_KEY ...` on that deployment, and check
  `ATELIER_WEB_URL` too. Consider a friendlier message than the env var name.

### F3. A turn's text renders twice

- Repro A (Claude): ask Claude to run `sleep 40`. Claude Code moves it to a
  background task, so the turn has two `result` messages. The whole answer
  shows in grey (streamed) and again in white (final).
- Repro B (Codex): any Codex turn whose answer spans two agent messages. Seen
  with "list your room tools".
- Cause: `streamedText` in `apps/web/src/components/room/TurnView.tsx:44` hides
  the final answer only when the streamed text ends with it exactly. Claude
  joins every result into the final (`runner/src/adapters/claude.ts:285`) while
  the stream inserts `\n\n` at every `message_start`, including tool-only
  messages (`claude.ts:260`). Codex's stream has no separator between agent
  messages while its final does. Any whitespace mismatch shows everything twice.
- Fix direction: compare with whitespace normalized, or have the runner report
  where the final answer starts in the stream instead of string matching.

## Medium

### F4. Steer is refused while the turn still shows "Working"

- Repro: same turn as F3 repro A. Queue a message and press Steer now: "Couldn't
  steer into the running turn, so it's still queued." The turn stays "Working"
  for ~40 s and the message runs next turn.
- Cause: `claude.ts:589` stops accepting steers at the first `result`, but the
  query stays open for the background task's follow-up.
- Impact: Steer now and Send and steer now are offered the whole time and can
  never work. The queue fallback is safe.

### F5. Send and steer now is offered when it cannot steer

- The composer shows it whenever the agent is running
  (`AgentComposer.tsx:56`). For a scribe turn or a thread-mention turn the
  backend quietly queues instead (`takesSteer`, `lib/dispatch.ts:267`;
  `messages.ts:256`), with no note. Seen during a scribe run.
- Fix: expose whether the active turn takes steers and hide the button (and the
  queue strip's Steer now) when it does not.

### F6. Room page scrolls sideways on a phone-width window

- At 386 px the document header's actions row (Call in the scribe, History,
  Save as template) is 358 px wide and does not wrap, so the page is 518 px
  wide and Save as template is off screen. Room list, templates, new room and
  invite pages fit.

## Low

### F7. Folded agent strip: badge text overlaps the bot icon

- Badge has a fixed 18 px height, which becomes its inline size under
  `[writing-mode:vertical-rl]` (`SidePanel.tsx:51`). "Working" (48 px) overflows
  upward over the icon. Same for "N questions" and unread badges.

### F8. Messages that changed a turn are listed after its reply

- A steered message ("Steered into the running turn") and a chat answer to a
  card ("Answered the question card") appear below the turn's final text, so
  effect comes before cause.

### F9. Shift+Enter line breaks in a block don't render

- Stored as `"line one\nline two"`, rendered as "line one line two" (markdown
  soft break), though the editor says "Shift+Enter adds a line".

### F10. Sending while scrolled up doesn't reveal your message

- `onSent` in `AgentPane.tsx:160` doesn't scroll; stick-to-bottom only holds
  when already at the bottom. Seen 1,247 px from the bottom after sending.

### F11. Claude isn't told a chat answer covers every question on a card

- Answering a two-question card by chat sends the same text to both (as
  designed), and Claude reported it as a possible bug. The card result or room
  context could say so.

### F12. Templates and new-room pages jump while you type

- The card is centred vertically, so it moves when validation notes appear or
  sections are added, and clicks land on the wrong control.

### F13. Invites have no member or duplicate check

- `invites.create` doesn't refuse an address that already belongs to the room
  (including the owner's own) or one with a pending invite. Read from code;
  not reachable live until F2 is fixed.

### F14. While a turn runs, a steered message shows below its reply

- Steer Claude during a running turn: the reply ("banana") streams in, and the
  "Steered into the running turn" message is listed under it. Once the turn
  ends, the message moves above the narration, where it belongs.
- Cause: a running turn's text is one live stream, and `TurnView` renders
  delivered messages after it. The stream has no marker for where the steer
  landed.
